1. **P1. Host API keys are included in tablet profile snapshots.** Reproduced. Source: [profile_snapshot.rs](C:/Users/nik/accessibility-keyboard/src-tauri/src/services/profile_snapshot.rs:44). `sanitize_settings_for_tablet` removes `groqApiKey` from the parsed `settings`, but `ProfileSnapshot.profile` still includes the original `Profile.settings_json`. The entire snapshot is serialized by `profile.snapshot`. A paired tablet therefore receives the key despite the comment and UI promise that it stays on the host. Remove raw settings from the tablet profile type or replace them with the sanitized JSON before serialization. The included `snapshot-regression.rs` checks the full serialized payload using a fake key and fails because that key is present.

2. **P1. Deleting an active custom profile overwrites the existing Default profile.** Reproduced. Source: [profiles/mod.rs](C:/Users/nik/accessibility-keyboard/src-tauri/src/profiles/mod.rs:254). When an active profile is deleted, `recreate_default_profile_locked` always resets the database and saves to `default.profile.json`, even when that file already contains another profile's settings, phrases, and macros. Create a customized Default, create Custom, then delete Custom. Default is overwritten. Load an existing remaining profile, and create Default only when no profiles remain.

3. **P1. Profile operations accept paths outside the profile directory.** Reproduced. Source: [profiles/mod.rs](C:/Users/nik/accessibility-keyboard/src-tauri/src/profiles/mod.rs:237). The backend joins caller-supplied filenames without restricting them to a basename or checking the resolved parent. `delete_profile_file("../unrelated.txt")` successfully deletes a sibling file. Load and Create have the same path-boundary problem. This is a backend command-boundary defect; the normal delete dropdown does not expose arbitrary paths. Validate filenames centrally, reject absolute paths and separators, require the profile suffix, and verify the resolved parent before writes or deletion.

4. **P1. Leaving the tablet dictation tab can leave the microphone recording.** Source: [DictationPanel.tsx](C:/Users/nik/accessibility-keyboard/companion/src/components/DictationPanel.tsx:43), [ConnectedScreen.tsx](C:/Users/nik/accessibility-keyboard/companion/src/screens/ConnectedScreen.tsx:237). The tab switch unmounts `DictationPanel`. Its effects unsubscribe from messages but never discard the module-level recorder on unmount. The `!enabled` branch only runs while the component is mounted. Start dictation and switch to Keyboard or Trackpad; no stop/release call runs. Add teardown that discards the recorder and terminates host dictation, including when asynchronous startup finishes after unmount.

5. **P1. Starting an already-running bridge deadlocks.** Source: [companion/mod.rs](C:/Users/nik/accessibility-keyboard/src-tauri/src/companion/mod.rs:72). `start` holds `self.runtime` while returning `self.ui_state()`. `ui_state()` calls `is_running()`, which locks the same non-reentrant mutex. A second Start cannot return, and subsequent bridge operations needing that mutex also block. Release the guard before reading UI state, or build the response from data already held. Cover repeated Start and rapid mode changes in a bridge integration test.

6. **P1. Unexpected socket errors skip host session cleanup.** Source: [server.rs](C:/Users/nik/accessibility-keyboard/src-tauri/src/companion/server.rs:96). Read errors and several send errors return through `?` before the cleanup block at line 233. If a tablet connection is reset after authentication, session state can stay Active, host audio stays routed to the tablet, and the minimized host is not restored. Use a cleanup guard or a connection-loop result followed by unconditional epoch-aware cleanup. Test resets and failed writes, not only clean WebSocket Close frames.

7. **P1. Stopping the bridge does not terminate accepted connections.** Source: [server.rs](C:/Users/nik/accessibility-keyboard/src-tauri/src/companion/server.rs:55). Connection tasks are detached and do not receive the stop signal. An already-accepted, unauthenticated socket can authenticate after Stop because the epoch check applies only after authentication. It can create a new active session even though the listener is stopped. Cancel and await all connection tasks on Stop and reject authentication once that bridge generation has ended.

8. **P1. Pairing and persistent credentials travel over plaintext WebSocket.** Source: [companionClient.ts](C:/Users/nik/accessibility-keyboard/companion/src/companionClient.ts:159), [auth.rs](C:/Users/nik/accessibility-keyboard/src-tauri/src/companion/auth.rs:30). The client uses `ws://`, sends reusable credentials directly, and does not verify the advertised host key. The advertised `pubkey` is random identity data, not an implemented encrypted channel. A network observer able to capture that traffic can recover credentials for a service that injects desktop input. Use an authenticated encrypted transport with a host identity verified during pairing. This was established from protocol code, not a network interception test.

9. **P2. An old socket can erase a newly connected socket.** Reproduced with mocked transport. Source: [companionClient.ts](C:/Users/nik/accessibility-keyboard/companion/src/companionClient.ts:182). Every socket's `onclose` unconditionally clears `this.ws`, stops pings, and rejects all requests. If an old close event arrives after the replacement opens, it destroys the new connection's state. Guard all handlers with the socket identity or connection generation.

10. **P2. Pairing after Forget disables automatic reconnection.** Reproduced with mocked transport. Source: [companionClient.ts](C:/Users/nik/accessibility-keyboard/companion/src/companionClient.ts:65). `disconnect` sets `intentionalClose = true`; `connectWithCredential` resets it, but `pair` does not. After Forget and a fresh pairing, the next dropped connection becomes Disconnected instead of Reconnecting. Reset connection intent when starting a new pair operation.

11. **P2. Disconnect cannot cancel a socket still connecting.** Reproduced with mocked transport. Source: [companionClient.ts](C:/Users/nik/accessibility-keyboard/companion/src/companionClient.ts:168). The socket is assigned to `this.ws` only in `onopen`. Calling Disconnect before that event cannot close it, and the pending connection can then authenticate and publish Connected. Store the connecting socket immediately and invalidate pending handshake continuations on disconnect.

12. **P2. A failed Create changes the active profile and destroys the current in-memory data.** Reproduced. Source: [profiles/mod.rs](C:/Users/nik/accessibility-keyboard/src-tauri/src/profiles/mod.rs:216). Database reset and active-filename persistence happen before writing the new profile succeeds. A name such as `missing-directory/child` resets the database and points the active filename to a nonexistent file before returning an error. Validate and stage the destination first, and commit database/file identity changes together or restore the old state on failure.

13. **P2. Free Write ignores the caret and selected text.** Source: [useFreeWritePhysicalKeyboard.ts](C:/Users/nik/accessibility-keyboard/src/hooks/useFreeWritePhysicalKeyboard.ts:90), [appStore.ts](C:/Users/nik/accessibility-keyboard/src/stores/appStore.ts:2569). The capture handler prevents native textarea editing and routes characters to an append-only buffer. Backspace always slices the final character. Clicking in the middle of a sentence or selecting text therefore does not edit the indicated location. Use textarea selection positions for both physical and on-screen input, or let the focused textarea process native editing.

14. **P2. Non-BMP characters are corrupted during input injection.** Source: [keyboard.rs](C:/Users/nik/accessibility-keyboard/src-tauri/src/input/keyboard.rs:77). `send_unicode` converts a Rust `char` to one `u16`. Characters above U+FFFF need two UTF-16 code units. For example, U+1F600 is truncated to U+F600. This affects text injection from phrases, dictation, and the companion. Encode with `char::encode_utf16` and emit the complete pair. The conversion defect is evident from the code; actual desktop injection was not exercised.

15. **P2. Literal text injection depends on the active keyboard layout and Caps Lock.** Source: [keyboard.rs](C:/Users/nik/accessibility-keyboard/src-tauri/src/input/keyboard.rs:217). `type_text_impl` sends ASCII letters, digits, and punctuation as hard-coded virtual keys. Those represent key presses rather than the requested text, so non-US layouts and Caps Lock can change the result. This affects companion `text.type`, phrases, macros, dictation, and suggestions. Use Unicode injection for literal text and retain virtual keys for shortcuts and physical-key behavior. Verify with Greek, AZERTY, and Caps Lock on Windows.

16. **P2. Deleting a profile leaves other windows using stale settings.** Source: [appStore.ts](C:/Users/nik/accessibility-keyboard/src/stores/appStore.ts:1196). Profile switching and creation emit `PROFILE_UPDATED_EVENT`; deletion does not. Deleting through Settings updates that window and the backend but leaves the main keyboard showing the old profile. A later main-window settings write can persist stale values into the new active profile. Invalidate pending writers before deletion and broadcast the completed change to all windows.

17. **P2. The committed Rust lockfile is stale.** Reproduced by the locked test command. Source: [Cargo.lock](C:/Users/nik/accessibility-keyboard/src-tauri/Cargo.lock:3301). The package version is 0.11.2 while `Cargo.toml` declares 0.12.0. Regeneration in the temporary copy changed only that version. Regenerate and commit the lockfile as part of the release version bump, then run locked checks in CI. Unlocked builds currently repair this silently.

The companion dependency audit should also be addressed before release. It reports high-severity findings for `@xmldom/xmldom`, `image-size`, and `js-yaml`, plus inherited Metro dependency entries. Seven entries do not mean seven independently exploitable flaws in the shipped APK. Review the affected dependency paths and exposure to untrusted inputs, apply compatible updates, and rerun the APK build and audit. Raw audit responses are saved alongside this report. No automatic dependency upgrades were made.

Code quality work should focus on test coverage and ownership before broad cleanup. No workflow under `.github/workflows` runs the test suites, Clippy, formatting checks, or the companion TypeScript check. The Windows build job also only runs on `dev` to `main` pull requests. Add checks on the branches where changes are integrated so these failures are caught earlier. The approximately 3,000-line application store mixes profile persistence, window management, input, teaching, and companion mode transitions. Splitting those responsibilities would make the state races easier to test. Profile imports clear and repopulate tables through separate database operations, and profile/auth JSON writes truncate the destination directly; add transactions and atomic file replacement to preserve recoverable state on failure.

The production frontend also bundles about 2.01 MB of JavaScript, approximately 591 KB gzipped, plus a 1.26 MB PDF worker. Vite reports the oversized chunk. Consider loading PDF and music import code when those modes are opened. This is a measured bundle-size issue, not a measured startup-latency result.

Reproductions are intentionally outside the normal passing suites. `node docs/audit/reproduce-companion.cjs` runs three expected-behavior checks against the real client and currently fails all three. `profile-regressions.rs` can be appended to the profiles module in an isolated crate copy; all three checks fail on the reviewed code. `snapshot-regression.rs` checks the complete serialized tablet response. Use temporary data only when rerunning the Rust regressions. They do not require real credentials, network traffic, or input injection.
